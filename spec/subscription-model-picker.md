# Подписки в селекторе модели

- Штатный селектор и `/model` показывают каждый включённый подписочный аккаунт, прошедший проверку входа и CLI, отдельным провайдером `dsh-subscription-<cli>-<номер>`. Внутри перечислены модели, которые сообщил сам CLI: Claude Code в ответе на initialize, Codex через `model/list` App Server. Чтение списка не вызывает модель. Пока список не получен, у аккаунта есть одна строка «Модель CLI по умолчанию».
- Выбранная модель передаётся CLI (`-m` у Codex, `--model` у Claude Code). Модель, которой нет в списке аккаунта, отклоняется до запуска CLI.
- Прежние маршруты `dsh-subscription-codex` и `dsh-subscription-claude` ничего не перечисляют, но чаты, где моделью выбран id аккаунта, продолжают работать на модели CLI по умолчанию.
- После хода в DSH уходит число токенов из отчёта CLI: кешированный ввод отделён от обычного, у Codex он вычитается из `input_tokens`. Поэтому статистика DSH и тем учитывает подписочные ходы под настоящим id модели.
- Статус входа, включение, выключение, переименование и удаление обновляют каталог без перезапуска. Текущая занятость и квота не убирают строку из каталога.
- Обычный чат выполняет запрос на выбранном аккаунте без API-ключей, автоматических повторов и переключения на другой аккаунт или API. Сбой, отсутствие CLI и исчерпание лимита возвращаются как ошибки.
- Обычные чаты не привязывают вендорскую сессию: каждый ход передаёт актуальный текст и до 80 000 символов видимого текстового контекста. Можно менять провайдера между ходами; выбор отправляет контекст этого чата выбранному провайдеру. Картинки текущего запроса передаются CLI, другие вложения не поддерживаются. Служебные сообщения и сырые результаты инструментов не включаются в контекст. Подписочный дочерний чат сохраняет прежнюю привязку к аккаунту и CLI-сессии.
- CLI выполняет команды в рабочем каталоге проекта по существующим правилам плагина и требует режим Harness «Полный доступ». Селектор не повышает права. Инструменты CLI записываются в историю, но не исполняются второй раз ядром Harness.
- Для обычного и дочернего чатов текст CLI передаётся штатными блоками потока Harness. Так итоговый ответ отображается в самом ходе, а не остаётся скрытой записью в журнале. Если CLI завершился без текста, ход показывает ошибку вместо пустого успешного завершения.
- Несвязанные с ходом вспомогательные вызовы не записывают результат в чат. Подключение и подтверждение подписки остаются в панели «Подписочные агенты».
